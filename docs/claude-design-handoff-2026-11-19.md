这份文档可以脱离此前聊天独立阅读。先按这里的用户目标和交互约定重审产品，再决定页面形式与组件样式。

- **已明确要求**：来自用户反复表达的产品目标、首发范围及反馈，是本轮设计必须满足的约束。
- **建议方案**：本稿为消除重复输入、跳转和确认而整理的流程方案，可以优化形式，但必须说明如何满足相同目标。
- **待确认规则**：目前缺少依据或尚未作出产品决定，必须显式呈现，不能由设计或代码悄悄替用户决定。

现有 UI、流程、参数公式和示例模型都只是工作原型，不应作为新设计的默认正确答案。优先处理保型、模型内编辑和流程连续性，再做视觉细化。

## 1. 产品定义与这次要验证的价值

**定位：老家具复原与适己化 DIY 工作室。**

普通用户带来喜欢的成品家具参考，AI 理解参考并建立可编辑模型；用户结合自己的身体尺寸、坐姿和制作条件调整设计，最终得到模型、图纸和加工包。

用户的核心意图是：**“我喜欢这把椅子，希望把它做成适合我的版本。”**

产品需同时守住两件事：保留这把椅子的设计特征；让修改真正进入可编辑几何与加工资料。不能为了满足人体估算值，把原椅子变成另一个产品。

这个 side project 首先验证：**三维设计到二维加工资料的自动化流程，对普通用户有价值、有吸引力，并能被独立完成。** 本轮先把开发和呈现做完整。投放、定价和收益策略另议，不把商业化假设写成已验证结论。

目标用户不需要懂 CAD、节点、孔轴或完整木工术语。主要任务是带来参考、表达需求、看懂影响、作出少量选择。

## 2. MVP 范围与产物

### 已明确要求

| 项目 | 要求 |
|---|---|
| 首发家具 | 餐椅 / 普通坐姿椅 |
| 风格与复杂度 | 首版达到石卷工坊风格平直板件家具的复原与调整水平；这是 MVP 能力目标，不是永久风格限制 |
| 参考输入 | 产品网页、图片、图纸及用户想法；已有参考不能要求重复输入 |
| AI | 真正参与理解参考、生成可编辑三维结构、提出尺寸与做法修改 |
| 应用形态 | 纯 Web、可交互、可编辑；可使用开源几何库 |
| 编辑器基础 | 选择、旋转、尺寸输入、部件树、测量、撤销/重做、视角控制 |
| Module | 保存个人身体数据与主要坐姿，给出受原设计约束的调整建议 |
| 输出 | 可编辑模型、PDF/SVG 图纸、加工包；加工包包括采购单、下料清单及五金清单 |
| 制作复杂度 | 以标准板材、平直板件、简单直角切割为基线；更复杂工艺必须明确是否支持 |

材料、板厚和初始做法优先根据参考网页、图纸和 AI 分析提出默认方案。仅在来源缺失、存在冲突或用户需要取舍时追问，不在入口堆一张专业参数表。

### 本轮不扩展的范围

多家具品类、复杂曲面与软包、通用专业 CAD 的全部功能、复杂制造工艺、营销投放及定价，不作为这轮完成条件。

模型与加工数据一致性检查，不等于整椅承载、稳定性、舒适性或实际加工结果已经验证。产品中应在相关决策处清楚表达，避免每一步重复展示长篇说明。

## 3. 用户、AI、Module 与几何规则的职责

| 角色 | 负责什么 | 不应发生的越界 |
|---|---|---|
| 用户 | 选择参考，填写个人数据，表达偏好，决定保型与适配之间的取舍 | 被迫提供大量可以推断的数据，或替 AI 整理专业建模指令 |
| AI | 分析参考，识别部件及关系，生成可编辑结构，推断缺失信息，提出可解释的修改与做法选项 | 以任意通用模板冒充对当前参考的复原；无提示地改变设计身份 |
| Module | 记录人体与使用目标，关联受到影响的设计尺寸，组织适配建议 | 把身高换算出的建议当成必须达到的几何命令 |
| 几何与校验规则 | 执行允许的修改，维护部件关系、连接、孔位与资料一致性，拒绝不成立的组合 | 只改目标字段而不改模型；遇到问题仍显示“完成” |
| 产品界面 | 让用户看清当前对象、变化、选择与下一步 | 暴露内部任务编排、原始节点和完整诊断列表来代替设计交互 |

AI 可通过结构化建模指令、工具或 skill 受到约束。具体工程机制可调整；对用户的承诺必须是可以看见、选择和编辑的结果。在线 AI、样例体验和模拟演示必须可区分，演示不能冒充真实参考识别。

## 4. 原设计与适己化：最高优先级规则

### 4.1 保留参考基线

原始参考和复原基线需要保留。用户后续修改的模型是其派生版本，随时能与基线对比或撤销。

AI 需针对当前参考识别：

1. **设计特征**：外轮廓、部件构成、支撑方式、关键比例和接合关系。
2. **可调参数**：能在保留这些特征的前提下修改的尺寸及关联部件。
3. **修改边界**：会破坏特征、导致连接失效或超出加工能力的变化。

这是针对具体设计的关系和规则，不是一张适用于所有椅子的固定尺寸表。识别不确定时，应把必要的判断交给用户，而不是把猜测当成已确认事实。

### 4.2 Module 建议的处理顺序

```text
个人数据与坐姿
    → 形成使用目标
    → 与原设计及制作约束一起评估
    → 在可调整范围内提出方案
    → 展示实际模型上的变化
    → 用户采用或修改
```

不能直接使用“身体数据 → 四个公式结果 → 无条件改变部件”的流程。

如果适配目标与原设计冲突，应在同一工作台说明具体冲突，给出有意义的选择，例如：

- 保留原设计特征，采用有限调整，并说明仍存在的使用限制。
- 查看单独的改款提案，明确哪些特征会改变，采用后成为新版本。
- 修改主要坐姿或补充必要信息，重新评估。

不应把不适合该构造的坐姿强行适配成功。用户选择“盘腿”也不意味着允许任意加宽、加深椅子。

### 4.3 本轮反例

现有案例的座板曾从 `400 × 215 mm` 变成 `655 × 448 mm`。用户认为结果与参考相差过远，不可接受。这个例子用于提醒设计团队：**几何能够生成、数值能够保存，不代表修改符合产品意图。**

保型不能仅通过“改动不超过统一百分比”解决。具体不变量、可调幅度和冲突策略尚需针对样例定义并验证。

## 5. 页面与信息架构

### 建议采用三个一级页面

| 页面 | 目的 | 进入 / 离开条件 |
|---|---|---|
| 开始制作 | 输入参考、想法，继续已有项目或体验案例 | 提交后直接进入设计工作台；不再增加构思填表中间页 |
| 设计工作台 | 围绕同一个模型完成复原、适己调整、做法和必要核对 | 只有真正进入交付资料时才转到加工包 |
| 加工包 | 查看和下载同版本模型、采购、下料、图纸及装配资料 | 返回设计时保留项目和工作状态 |

三个一级页面是收敛方案，不要求照搬当前页面样式。必须保持的约束是：**Module、做法、核对都属于同一工作台里的状态，不能各自变成一套独立表单页面。**

### 工作台布局的硬性要求

- 三维模型是视觉和操作中心，不能为了容纳面板而把模型压成小缩略图。
- 用户不接受左、中、右三栏同时铺开信息。辅助信息应合并为一个操作区域。
- 最新原型选择底部浮动操作面板作为交互基线；Claude 可以优化形式，但不能让输入和操作在左侧、底部、弹窗之间来回迁移。
- 单项操作时，仅展示该对象、必要输入、简短依据和下一步。
- 部件树、原始资料、版本、详细检查、完整参数按需打开，不默认全部平铺。
- 面板收起由用户控制；普通步骤推进和窗口变化不能无故开合面板。
- 在桌面常见窄窗口下，仍需保留模型与操作区域；不能直接隐藏模型、变成整页表单。
- 完成态应明显短于编辑态，只显示结果摘要与下一步，不保留一个空的大面板。

## 6. Golden Path：从参考到加工包

以下按“用户动作—界面反馈—下一状态”定义，不要求每一行对应一个页面。

| 阶段 | 用户动作 | 系统与画面的预期 | 下一状态 |
|---|---|---|---|
| 1. 带入参考 | 粘贴链接、添加图片/图纸，简述想法 | 显示参考缩略图或内容摘要；多个同源参考合理合并，避免重复条目 | 开始生成 |
| 2. 参考理解与复原 | 点击一个明确的开始动作 | 直接进入工作台；主画面显示真实处理状态，底部保留取消/必要补充入口 | 主画面出现可编辑候选 |
| 3. 看第一版 | 旋转查看，对照参考 | 能看到整体形态与部件；主要材料和不确定假设按需查看 | 沿用此版继续，或提出修改 |
| 4. 个人 Module | 在模度人示意中修改身高、坐高、臀宽，选择主要坐姿 | 输入与人体标注对应；保存后保留档案，模型不消失 | 受原设计约束的尺寸建议 |
| 5. 适己调整 | 点击模型尺寸标注输入数值，或采用当前建议 | 展示变化、关联部件与必要的取舍；采用后实际几何和已保存数值一致 | 下一项有必要的决定 |
| 6. 选择做法 | 点选部件/连接，沿用或修改材料、板厚、连接 | 在装配状态的模型中定位，展示少量可行方案及影响 | 设计方案具备出包条件 |
| 7. 必要核对 | 逐项解决真实问题或未作出的选择 | 同一工作台、一次一项；已完成决定不重新确认；默认不展示加工图纸 | 无阻塞时可生成加工包 |
| 8. 交付 | 点击生成加工包 | 生成状态明确；成功后进入加工包，模型、图纸、采购和下料绑定同一版本 | 查看、下载或返回修改 |

“沿用此版继续”可以同时完成候选采用和进入下一状态，不应再弹出一个内容相同的确认框。生成结果需要有采用语义，但不需要叠加重复操作。

## 7. Module 输入与尺寸编辑的详细交互

### 7.1 身体数据：三项输入，一组姿势选项

默认仅要求：**身高、坐高、臀宽**。主要坐姿提供 **正坐、靠坐、斜靠、盘腿** 等选项，配简单图形或短说明，不让用户自己写姿势描述。

以柯布西耶模度人的视觉概念作为母本：用户看见参考人物及尺寸标注，将相关数字改成自己的数据。人物示意与输入必须建立清楚对应关系，避免图在一边、无关表单在另一边。

- 参考值须明确是参考/示例，不能当成用户已填写的数据保存。
- 不把本产品补充的坐高、臀宽示例误称为柯布西耶原始理论数值。
- 未测量的身体参数允许估算，但不默认暴露成必填项。
- cm/mm 可直接输入或切换，并正确换算；不得反复要求用户计算单位。
- 保存后再次进入时展示个人数据，修改入口清楚；不让用户每个步骤重复填写。
- 修改身体数据后，重新评估受影响建议；已有模型保留，直到新的修改被采用。

### 7.2 尺寸在模型上直接编辑

| 动作 | 预期反馈 |
|---|---|
| 选择座板或坐姿 Module | 显示与当前选择相关的尺寸线，不把所有部件尺寸同时铺满画面 |
| 点击尺寸数字 | 原位置或紧贴标注出现输入控件，焦点进入数值 |
| 输入数值、单位或简单算式 | 显示换算后的目标值和模型预览；例如 `42 cm`、`400+20 mm`；非法内容保留在输入中并解释 |
| 输入合法且符合约束 | 预览关联部件变化，不提前覆盖已保存版本 |
| 按 Enter / 点“下一个” | 采用当前有效修改；“下一个”同时推进当前建议，不再出现第二次确认 |
| 按 Esc / 取消 | 恢复修改前的有效模型及数值 |
| 超出保型或制造边界 | 同处说明影响并提供可行选择，不默默限制数值、不假装成功 |
| 撤销 / 重做 | 恢复整次关联修改，包括尺寸、部件和受影响的做法状态 |

“输入表达式”的范围是简单长度计算和换算，不需要通用编程表达式能力。支持形式和错误提示需在设计中明确。

### 7.3 尺度感知与名词

- 默认通过模型上的尺寸线、明确端点和原版/调整后对照帮助理解，不能用两个无方向的悬空矩形代替。
- 人体轮廓可以辅助尺度感知，但估算轮廓不代表舒适性或真实姿态已验证。
- “座板前后长度”和“有效坐深”是不同概念，必须按实际测量对象命名。
- 当前原型的 `seat_depth_mm` 表示座板前后长度。若未来引入有效坐深，须定义靠背接触面、测量方向和与板件尺寸的关系，不能只改显示名称。
- 屏幕上的当前值、建议值、预览值、已保存值要区分；概览默认展示已采用值，不能重新计算建议覆盖用户选择。

### 7.4 尺寸推进的简化原则

用户要求“一次确认一个”，意味着**一次只处理一个有意义的决定**。不意味着所有用户必须固定点完四次相同的确认。

建议：无变化且无问题的项目可以沿用；存在真实调整或取舍时逐项展示。最后一项完成后显示紧凑摘要，直接继续做法。

## 8. 做法编辑：必须有选择和修改机会

进入做法时，AI 应已基于参考提出一版初始方案。用户可以沿用，也可以主动选中部件或接合处修改。

| 对象 | 最小可编辑内容 | 预期影响展示 |
|---|---|---|
| 部件 / 材料 | 支持的材料、板厚 | 外观、尺寸、连接和采购变化 |
| 连接 | 当前构造下可实现的连接方式 | 是否可拆、可见外观、加工要求、关联零件 |
| 五金 | 该连接支持的规格和数量方案 | 适用板厚、孔位、采购变化 |

不能把任意连接方式都列成可选项。无效组合应解释原因，可行替代方案应具体；“让 AI 完善一下”不能代替完整的修改入口。

采用修改后，模型、孔位与清单同步变化；只将真正受影响的连接或决定标为需要重新核对，不能要求整套流程从头再来。

### “在模型查看”的约定

1. 保持整椅装配状态。
2. 高亮相关部件/接合处，必要时轻微调整视角。
3. 在原有操作区域说明当前问题或可改参数。
4. 返回时恢复原选中状态、视角或当前步骤，不跳到另一个大型页面。

不得默认展示爆炸、全量分料、节点列表和加工大样。局部透明、剖切或分解可以作为必要时主动开启的辅助操作。装配步骤和完整爆炸图主要放在加工包。

## 9. 出包前核对与加工包

### 出包前只核对真实问题

按性质区分：

| 类别 | 处理规则 |
|---|---|
| 真正阻塞 | 缺少必要尺寸、无效几何、连接不成立等。定位并提供修正路径；解决前不能声称可制作 |
| 未作出的决定 | 例如存在两种可行连接而尚未选择。一次展示一个决定 |
| 非阻塞说明 | 折叠记录，在相关位置可查看；不靠连续复选框推进 |
| 已采用且未受影响 | 直接沿用，不重新逐项确认 |

设计核对默认围绕模型进行，不强迫用户阅读加工图纸。没有待处理问题时，直接提供生成加工包的动作。图纸预览和下载出现在加工包阶段。

### 加工包组织

围绕三个用户问题组织资料：

- **我买什么**：板材、五金和采购信息。
- **交给加工店什么**：零件编号、下料清单、PDF/SVG 图纸和必要加工说明。
- **我怎么装**：装配顺序、连接做法、对应五金和按需的分解示意。

同时提供可编辑模型数据。PDF/SVG、采购与下料的具体下载组织由设计提出，但必须真实可用，不能只有入口。

返回设计修改后，旧加工包保留版本标识，新设计需要重新生成对应资料；不把旧图纸与新尺寸混用，也不把旧版本直接删除。

## 10. 必须设计的边界分支

| 情况 | 用户应看到什么 / 能做什么 | 不允许的结果 |
|---|---|---|
| 网页无法读取 | 保留已输入链接，说明无法读取的部分，允许补图/图纸或继续其他有效参考 | 重新要求从头填写全部内容 |
| 参考缺少关键尺度 | 在工作台提出一项明确补充，或提供标明估算的候选 | 把估算当作精确复原 |
| AI 未配置、失败或超时 | 区分配置缺失、正在处理和失败；可重试/取消；保留当前有效设计 | 空按钮、假进度、无结果却显示成功 |
| 候选与参考不符 | 同一画面可对比，用户指出哪里不符并继续修改 | 默认把候选作为已批准设计 |
| 主要坐姿不适合原构造 | 说明冲突，提供有限调整/修改目标/查看改款等选项 | 按公式强行拉伸椅子 |
| 输入为空或无法换算 | 输入旁提示，保留内容，不能推进此项 | 将空输入解析成 0 并保存 |
| 关联修改失败 | 保留修改前有效模型，指出失败部位及可行操作 | 部分部件更新、总览却宣布全部完成 |
| 用户返回前一步 | 已填内容、当前版本和选择保留 | 清空数据、重启生成、无故收起面板 |
| 修改板厚影响已确认连接 | 仅重新评估受影响部分，解释原因 | 默默继续使用旧孔位和旧五金 |
| 其他标签页修改了项目 | 提示版本变化，保留本地未提交输入并允许核对 | 覆盖新版本或显示旧模型却声称同步 |
| 刷新、重开项目 | 恢复已保存设计；保存状态与未提交编辑清楚区分 | 返回无关空白流程或丢失已采用数据 |
| 窗口变窄 / 面板展开 | 保留可用的模型区域，操作仍在同一位置 | 隐藏模型、意外全屏表单或自动缩成缩略图 |
| 图纸/加工包生成失败 | 保留已确认设计，显示错误和重试入口 | 回退为未设计状态或提供不可下载的“完成”页 |

## 11. 暴露什么，收起什么

| 默认可见 | 按需展开 | 不应作为普通用户默认界面 |
|---|---|---|
| 当前模型、当前对象、有关尺寸、当前决定、一个主要推进动作 | 参考原图、部件树、完整参数、建议依据、版本、材料/连接详情 | 内部节点图、原始 JSON、任务路由、完整错误堆栈 |
| 当前生成/保存状态、需要处理的真实冲突 | 原版对比、局部剖视、必要的辅助测量 | 全模型所有尺寸、所有连接与所有警告同时展开 |
| 当前采用的数值和修改结果 | 估算来源及未验证事项 | 用重复确认框表达系统不确定性 |

部件树与测量属于首发可用能力，但“可用”不意味着常驻铺开。图纸属于交付物，不能提前挤占设计工作台的主流程。

## 12. 现有原型必须修正的偏差

1. 人体建议曾直接驱动几何扩张，缺少针对参考的保型规则。
2. 总览曾混用已保存尺寸与重新计算的建议值，导致用户自定义值看似失效。
3. 保存后的模型刷新曾等待检查和加工资料派生，缺少及时的可见反馈。
4. 辅助面板开合、布局断点曾隐藏或压缩模型，破坏视觉焦点。
5. 做法阶段更多是接受现成方案，缺少完整的可修改选项和联动结果。
6. 核对曾提前展示图纸、复杂清单和重复确认。
7. “在模型查看”曾进入复杂的连接/分解展示，偏离简单定位预期。
8. 尺寸主要在面板填写，尚未形成完整的模型标注直接编辑体验。

此前已有局部修复，但不把这些修复视为最终设计。当前样例中六板椅的确定性几何联动，也不能代表任意参考已完成 AI 复原。

## 13. 交互验收场景

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A01 | 输入参考与想法并开始 | 只输入一次，直接在工作台看到处理状态和结果；没有重复构思表单 |
| A02 | 对照参考查看初始模型 | 关键轮廓、部件构成和比例能对应；无法确定处标明，不能由通用样例冒充 |
| A03 | 输入三项身体数据与主要坐姿 | 可以保存和修改；其余估算项不成为默认必填 |
| A04 | 接受一个保型范围内的尺寸修改 | 模型几何、标注、已采用值、关联部件和新资料一致 |
| A05 | 输入明显改变原设计的尺寸 | 出现具体取舍或改款提案，不能无提示变形成功 |
| A06 | 点击模型上的尺寸并修改、取消、撤销 | 数值可直接输入；预览、采用与取消语义清楚；撤销恢复整次关联修改 |
| A07 | 自定义值与公式建议不同 | 总览显示自定义已采用值；建议不能覆盖它 |
| A08 | 更换材料/板厚/连接方式 | 有真实可选方案；模型与加工信息同步；受影响核对范围明确 |
| A09 | 点击“在模型查看” | 定位正确，仍保持整椅装配状态，无默认爆炸和复杂节点列表 |
| A10 | 完成所有必要选择后出包 | 不再逐连接重复确认，不强制先阅读图纸 |
| A11 | 生成并下载加工包 | 模型、图纸、采购、五金和下料来自同一设计版本，文件能够打开 |
| A12 | 返回修改后再次出包 | 旧包有旧版本标识，新包反映新设计 |
| A13 | 在常见桌面宽屏与约 800px 窄窗口使用 | 模型仍是主体，面板不把模型隐藏或压成缩略图，按钮可达 |
| A14 | 生成失败、几何失败、版本冲突 | 有明确原因与恢复动作，当前有效设计和输入不丢失 |

体验验证建议记录：独立完成率、需要他人解释的节点、重复输入/确认次数、模型与产物不一致次数、用户对原设计保留程度的评价。目标数值和招募人数尚未确定，不编造验证结果。

## 14. 待确认的产品规则

这些事项可以由 Claude 提出具体方案，但不能默认为已定：

1. **样例的保型边界**：哪些部件关系必须保留，哪些尺寸允许调整到什么范围；如何识别已跨入改款。
2. **尺寸语义**：对普通用户使用“座板前后长度”还是“有效坐深”，两者如何呈现和联动。
3. **坐姿承诺**：四种姿势都可表达需求，但首发构造能实际支持哪些适配，何时需要换构造。
4. **制造边界**：用户要求简单直角切割，而现有样例含倾斜靠背与斜切处理；斜切是否纳入 MVP，不能隐式扩大。
5. **做法选项范围**：首发哪些材料、板厚、连接和五金组合已经有足够规则与验证可供选择。
6. **PDF 交付方式**：直接生成可下载 PDF，还是先提供可打印页面；用户期待 PDF/SVG，但具体实现方式未定。
7. **小屏下限**：桌面窄窗口必须可用；手机是否需要首发提供同等编辑能力尚未决定。
8. **AI 复原验收**：首发参考集、关键形态与尺寸的准确性标准、允许的补充信息和失败恢复策略，需要具体定义，不能仅以“生成了模型”作为通过。
9. **个人档案保存范围**：保存身体数据已确定；跨项目自动复用、多个人物及覆盖旧档案的规则尚未决定。

不需要重新询问已经明确的产品定位、椅子首发、三项身体数据、模型中心和一步一步的交互原则。
