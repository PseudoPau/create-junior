# Create Junior 产品设计

2026-11-19 更新。流程基线见 [交接稿 v2](design-handoff-v2.md)，本轮会话 Agent、角色分工和实现修正见 [实施记录](session-agent-iteration.md)。本文描述目标，实施与验证分别记录。

## 1. 产品要交付什么

用户带来一把喜欢的成品椅子，拿走一把适合自己、能交给加工店或自己动手的同款。交付的是一个具体项目：参考依据、原版基线、适己修改、做法、图纸和装配资料保持一致，并能继续修改。

目标用户是没有 CAD 经验、愿意测量和装配的 DIY 初学者。加工店是资料的接收者。

核心规则：默认保持原椅子，只改它与使用者不合、而且这把椅子允许改的地方。

## 2. 三个页面

| 页面 | 回答什么 | 进入与离开 |
|---|---|---|
| 开始制作 | 你想做哪把椅子 | 提交参考即开始生成，直接进入设计工作台。也可以从案例开始，或继续已有项目 |
| 设计工作台 | 复原、适己、做法三步，围绕同一个模型 | 生成加工包时才离开 |
| 加工包 | 我买什么、交给加工店什么、我怎么装 | 返回设计时项目和工作状态都保留 |

**开始制作。** 主输入接受链接、图片、图纸和文字，可以一起给。不要求先填产品名称。选择案例会复制成用户自己的项目，案例不能用来替换用户的参考。有历史项目时同时显示最近项目。服务配置放在设置里。

**设计工作台。** 三维模型是画面和操作的中心，辅助信息只占一个操作区，不做左中右三栏。每个时刻只有一个主要推进动作。直接改数值、对 AI 说、采纳建议，操作的是同一个项目、同一种修改动作。布局约束见 [交接稿 v2 §4](design-handoff-v2.md)。

**加工包。** 采购、图纸和装配资料绑定同一版本。当前可直接下载 PDF 和包含 SVG、CSV、可编辑 JSON 模型的 ZIP。返回修改后保留旧包，新设计重新生成。采购表按毛坯逐件列出，尚不计算整板排版及采购整板数量。

## 3. 流程

| 步骤 | 用户在回答 | 结果 |
|---|---|---|
| 1 复原 | 这是我要的那把椅子吗 | 原版基线：形、尺寸、默认做法、保型档案 |
| 2 适己 | 它哪里不适合我 | 只处理与使用者不合的几项尺寸 |
| 3 做法 | 我打算怎么做 | 沿用默认做法，或修改材料、板厚、连接 |
| 4 出包 | — | 加工包 |

三条贯穿规则：修改只有一种动作；第 2、3 步是推荐顺序而不是门槛；没有单独的“确认”步骤，核对是出包的条件。每一步的交互、分支和验收见 [交接稿 v2 §2–§7](design-handoff-v2.md)。

## 4. Module 是什么

`Module` 不是板材模数，也不是把零件重新分组。它描述谁、以什么姿态使用这把椅子，位于用户意图和物理实现之间：

```text
参考 / 使用意图 → Module → 部件 → 连接 → 图纸、清单、装配
```

- Module 保存身体数据、主要坐姿、使用目标、依据和状态，并关联受影响的部件。
- 部件是几何的事实来源，连接是制造的事实来源。Module 不替代它们。
- Module 给出的是**适合范围**，不是必须达到的尺寸。它要和原椅子的值、这把椅子的可调范围一起比较，才能形成建议。
- 用户直接改了某个部件时，相关 Module 标为需要重新比较，不做静默的双向覆盖。

在界面上，Module 出现在适己这一步：用户在模度人示意上填身高、坐高、臀宽，选一个主要坐姿。它不是一个单独的页面或步骤。首个 Module 是 CAFE CHAIR 的“坐姿支撑”。

## 5. 分工

- **AI**：理解参考，必要时追问，生成可编辑结构，识别特征和可调范围，把修改要求转成结构化修改，解释影响。AI 的输出必须是可编辑对象，文字回复或渲染图不能冒充建模完成。
- **产品规则**：单位、几何和约束、部件与连接的关系、影响范围、版本一致、图纸清单派生，以及明确可执行的检查。
- **用户**：选择参考，填写身体数据，表达偏好，决定保型与适配之间的取舍。
- **加工店或专业人员**：真实材料、工具、工艺公差，以及其能力范围内的工程复核。

在线模型、当前聊天协作和人工协作使用同一种候选协议。对用户来说都是“提出需求 → 看修改 → 采用或继续改”。在线 AI、样例体验和本地演示必须能区分，演示不能冒充对参考的识别。

不要让初学者替代工程校验。连接是否成立由系统检查；用户只在确有选择时做决定。几何检查不覆盖的承载、稳定性等事项单独标注，不能靠勾选变成验证通过。

## 6. 状态与回退

项目所处的步骤、AI 任务状态和加工包状态分开表达。一次 AI 修改正在生成或失败，不影响已有模型。

**AI 任务**：准备输入 → 处理中 → 需要补充 / 可预览 / 失败 / 已取消；可预览 → 已采用 / 已放弃 / 版本已过期。只显示服务实际返回的阶段，不显示虚构进度。失败时有原因、保留的内容和重试入口；离开后回来能恢复。

**加工包**：草稿预览始终可看；送审或询价包带着未知项和待复核清单；正式的加工包要求相应信息和复核记录完整，并显示检查覆盖范围。首发交付到哪一级由产品负责人决定。

**版本**：任何设计修改都让旧加工包保留为历史快照，新版本需要重新生成。采购、加工和装配清单引用同一版本。

异常分支的处理见 [交接稿 v2 §6](design-handoff-v2.md)。另有两条实现层面的约束：

- PDF 目前只保存不解析，界面按实际处理能力表达，不把上传成功说成已理解。
- 不支持的曲面或隐藏结构要定位到对象，允许简化方案或补充参考，不用渲染图掩盖模型缺失。

## 7. 对标 Flatma

Flatma 官方帮助展示了从 AI、目录或手动开始，到可编辑部件、材料连接、参数化、检查、开料、图纸、下载及装配的连续流程。对标的重点是模型修改能持续传递到制作资料，以及用户能重新找到并继续项目。来源：[Flatma 帮助](https://flatma.com/zh/help/)（2026-11-17 查阅，是文档中的能力描述，没有逐项亲测）。

Junior 的重点是成品参考的复原、适己，以及对新手的制作引导。专业建模工具、社区和空间规划在主流程稳定后再扩展。

## 8. 验收与衡量

交互验收场景见 [交接稿 v2 §7](design-handoff-v2.md)。另有一项交付验收：请一位没有参与设计的加工接收者，只看加工包、不看聊天和 JSON，判断能否完成加工准备并列出缺项。之后用样件验证装配。

用户测试建议：5 位无 CAD 经验的用户试做同一把椅子，记录首次看到模型的时间、需要他人帮助的次数、推进点击次数、完成适己和取得可读资料的比例。建议目标是至少 4 位独立完成主路径，这是待验证的目标，不是当前成绩。

模型检查单独记录：有效参考的成功率、关联修改的成功率、连接和图纸的一致性、失败恢复率。固定案例和在线生成分开统计。下载成功不能代替实物制作成功。
