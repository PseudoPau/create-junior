# 主线、修改与测量

2026-11-24 · 提案；可点骨架稿 v2 见 [design/proposals/mainline-2026-11-24.html](../design/proposals/mainline-2026-11-24.html)。
依据：确认稿 [junior-visual-review-preview.html](../design/approved/junior-visual-review-preview.html) 的信息清单；[开放体验评估](open-experience-review-2026-11-24.md) 的实测。

## 一句话

**主线只回答三个问题：像不像、合不合适、出不出包。修改是独立的高级模式；无论走多深，主线位置不变，随时一键回来。**

左栏长和跳转乱是同一个病：把工作台做成了向导。确认稿的密度本来是对的，实现时每页都加了说明和折叠，又把“一次一个决定”做成了“必须逐个确认”。

## 1. 主线：三步，不再有“做法”

```text
01 复原            02 适己                 03 加工包
这是你要的椅子吗 →  按身体调一下吗（可选）→  可以出包了吗
[就是这把，继续]    [看看建议] / [保持原样]   [下载加工包]
[修改这把椅子]      [改身体数据]             [回到椅子]
```

- **复原**：承认或否定第一版。只留参考缩略、一行参数、两条特征。
- **适己**：一次填身高／坐高／臀宽＋坐姿；只列不合的项；可以整步跳过。建议在一张卡里逐项采用，不再五项逐页确认。
- **加工包**：默认做法由模型带上；采购、图纸、装配、下载、历史版本都在这一页。
- **做法不再是主步骤**。材料、板厚、连接、五金都是修改；默认沿用，只有真正定不下来的才在出包前以“还差 1 项”出现。

这会改动 brief 的四步说法：**复原 → 适己 → 出包**，做法并入高级修改。默认做法和假设仍进加工包，并标“沿用默认”。

### 左栏规则

1. 只留三块：**问题**、**当前对象/数值**、**一个主操作**；次操作降为文字链接。
2. 正文最多 2 行；超过就是详情。详情收进标题右侧的 `i`，不再用三角折叠。
3. 一屏一个主按钮；主流程不放 `<details>`。
4. 阶段导航放在左栏顶部，做成 3 段胶囊（当前项白底浮起）；顶栏只留品牌、项目、设置、新设计。
5. 修改模式替换同一块导航：同宽、同位置的“高级修改”卡，不再出现第二条顶栏或第二套进度。
6. 字号：H1 26、关键值 28–32、正文 13、元信息 10.5–11；accent 只给当前步、数值和链接。

目标复原页就是：标题＋`i`、参考卡、两条特征、两个动作。现在多出来的样例长段、检查结果、模型组成全部移走。

### 视觉

- 一个顶栏：品牌／项目／设置／新设计；不放阶段，不放进度。
- 左栏顶部是唯一导航：3 段胶囊步骤。修改模式换成“高级修改”卡，占同一位置。
- 画布左上角只放状态 chip（`主线 · 复原` / `修改中 · 主线未变`），它是状态，不是第二套导航。
- 软表面：米白面板、12–14 px 圆角、轻阴影；主按钮用墨色，terracotta 只做当前步骤、数值和链接。
- 画布 chrome 用半透明胶囊（视图、测量），不再占一条横栏。
- 留白是层级，不是空白：复原页只有三个块，其余进 `i`。
- 窄屏（约 800 px）：模度主图缩到 150–180 px，步骤只留数字和当前标签，`修改` 收回图标；底部主操作始终可见。

## 2. 修改：独立模式，不是第四个步骤

入口只有四个，都指向同一层：

- 左栏步骤条右侧的“修改”；
- 复原页的“修改这把椅子”；
- 加工包里的“还差 1 项 · 处理”；
- 选中某个部件后的“修改”。

进入后：

- 左栏顶部换成等宽的修改卡：**`← 返回主线` + 面包屑 + “主线停留在 01 复原 · 未被修改” + Esc**。
- 步骤胶囊消失；画布左上角 chip 变成 `修改中 · 主线未变`——修改不是一步，用户不会以为自己“跳到别的地方”。
- 左栏是 `尺寸 / 材料 / 连接 / 测量` 四个页签；一次只看一个对象。
- 改动先预览；`采用` 才写入主线，`取消` 或返回主线都保留原设计。
- 底部保留“修改记录 · N 处未采用”和“放弃全部”。

### 兔子洞：随时能回来

| 原则 | 具体做法 |
|---|---|
| 主线永不消失 | 左栏顶部修改卡常驻，写清“主线停留在 02 适己 · 未被修改” |
| 一个明确出口 | 修改卡 `← 返回主线`、底部同名文字、Esc；三个都能立刻回 |
| 修改不自动写主线 | 预览与采用分开；返回不弹确认框，直接回，主线不变 |
| 改款另存 | 超出保型范围时标“改款”；采用后主线显示“已改 1 处 · 查看原版”，原版保留 |
| 不跳页 | 修改层内只有页签和聚焦，不出现“下一个确认”式的页面链 |
| 未采用可放弃 | 修改记录里一键“放弃全部”；离开即等于保留原设计 |
| 刷新/后退 | URL 带 `stage` + `mode` + `focus`；后退关闭修改层，不退出应用 |

用户走多深都不怕：**深度只增加面包屑，不增加主线状态。**

## 3. 模度：核心不是一张表单

Module 就是“坐姿支撑”：身高 / 坐高 / 臀宽 + 主要坐姿 + 使用意图。它是这件产品和普通家具编辑器的区别，不能缩成三个输入框。

- **适己主画面**：放大模度人图（站姿量身高，坐姿量坐高与臀宽），三项数字贴在图上；示例是示例，不冒充用户数据。
- **建议卡**：写清 `坐姿支撑 · 170 / 88 / 38 · 正坐`；每条建议带原值、适合范围、可调范围；只列不合的项。
- **加工包**：`模度 · 坐姿支撑 · 170/88/38 · 正坐` 随包带出，和版本绑定。
- **高级修改**：座宽、材料、连接的判断引用“坐姿支撑有没有建议”，不另起一套公式。
- 不单独做页面；它是适己这一步的实体。骨架稿里把模度人放大成主图，就是这个意思。
- 后续可把坐姿人形叠到模型上；本轮先用模度图做主输入，避免用假人体轮廓冒充测量。

## 4. 测量：把画布变成检查工具

### 现状

- 只有两次点击：`pick()` 在 `pointerup` 取面点，`addMeasurePoint()` 第二次点击后画线并报距离。
- 没有 `pointermove`，没有边线识别、悬停高亮、实时长度；左上角只在第二次点击后显示结果。
- 量的是任意两个面点的空间直线距离，不知道边、端点或面。

### 目标交互

| 阶段 | 左上角 HUD | 画布 |
|---|---|---|
| 待命 | 移到边线读取长度 | 十字光标 |
| 悬停边线 | `边线 400 mm` · 点击设起点 | 该边高亮、两端点出现 |
| 已设起点 | `起点已定` · 移到终点 | 起点圆点，线跟随鼠标 |
| 悬停终点 | **`距离 312 mm`** · 边 400 mm · 点击确认 | 实时线 + 吸附点 |
| 完成 | **`312 mm`** · 点击再测 · Esc 退出 | 固定线 + 中点数值标签 |
| 比例未确认 | `模型距离 312 mm` · 比例未确认 | 同上，加提示 |

### 命中与吸附

- 屏幕距离 10 px 内优先吸附：**端点 > 边线 > 表面点**；HUD 标“端点/边上/表面”。
- 只对可见木构件生效，排除五金；透视下用屏幕像素阈值，不用固定毫米阈值。
- 悬停边线读这条边的真实三维长度；设起点后读两点真实空间距离，不是投影长度。
- 完成后再次点击开始新测量；Esc 先清当前测量，再按一次退出工具。
- 没有确认尺度时，HUD 必须写“模型距离 / 比例未确认”，不能冒充实测。
- 测量在修改层里，属“检查工具”；主线不出现测量按钮。

### 实现要点

- `web/viewport.js`：缓存每个 mesh 的 `EdgesGeometry` 线段；加 `pointermove`（rAF 节流）、`pointerleave`；屏幕空间最近边；高亮覆盖线 + 端点；`pick` 在测量模式下取吸附点；`onMeasure` 带 `phase / edgeLength / distance / snap`。
- `web/studio.js`：主线三态、修改层、HUD 文案；切换工具/换页时清空；比例状态从 project 传入。
- `web/studio.css`：左栏胶囊步骤、修改卡、左上角 HUD、`i` 详情面板、模度主图。
- 触屏没有 hover：第一次点选边并显示，第二次点设起点；桌面优先。
- 不做：孔径/圆心识别、角度测量、任意两点云测量。

## 5. 点击对比

| 场景 | 现状 | 目标 |
|---|---|---|
| 样例，什么都不改 | 18 | **4**（打开样例 → 继续 → 保持原样 → 下载） |
| 填身体数据，采用 1 条建议 | 18 起 | 7 |
| 改座宽，作为改款 | 18 起 | 6–7：修改 → 输入 → 预览 → 采用 → 返回 → 下载 |
| 刷新后看刚生成的包 | 重新生成 | 直接恢复 |

关键不是省几次点击，而是：**没改的东西不再出现在路径上**。

## 6. 需要后端配合

- `POST /review/confirm` 接受 `decision='default'`；`app/workbench/models.py` 的 `ReviewConfirmation.decision` Literal 增加 `default`；`review_projection.complete` 把 default 视为已解决，加工包标“默认”。
- `GET /projects/{id}/exports` 已存在；再加 `GET /exports/{revision}` 返回 manifest + `package_snapshot`，用于刷新恢复加工包页。
- 现有 `POST /exports` 已幂等（同版本直接返回 manifest），刷新后重新生成不会产生重复包。

## 7. 建议顺序

| 阶段 | 内容 | 工作量 |
|---|---|---|
| 0 | 骨架稿：主线三态、修改层、测量 HUD | 已完成，见上方链接 |
| 1 | 左栏胶囊步骤 + 模度主图 + 减负 + `i` 详情层 | 1–1.5 天 |
| 2 | 修改层：尺寸/材料/连接、预览/采用、返回主线、修改记录；default 确认；刷新恢复 | 2–3 天 |
| 3 | 测量：hover 边线、实时距离、两次点击、HUD | 1–2 天 |
| 4 | 800 px、主路径、下载与刷新回归，更新文档 | 0.5–1 天 |

阶段 1 不动行为，风险最低；阶段 2 要改确认语义；阶段 3 独立。

## 不做

- 不改视觉风格、不改两栏布局、不回到三栏。
- 不做完整 CAD、曲面、装配仿真、手机端同等编辑。
- 不把测量结果写进模型尺寸，测量只读。
