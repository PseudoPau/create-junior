# 迭代说明

本记录区分“已有事实、正在实现、后续目标”。产品设计方向于 2026-11-17 获项目负责人认可；技术与产品细节按每轮结果继续调整。

## 原型基线 · 2026-11-17

**目的**：证明参考资料、候选、适己修改、做法和图纸可以围绕同一个项目连接起来。

**已有结果**：会话辅助完成 CAFE CHAIR 走查，得到 6 个部件、5 处连接、34 件五金和 11 张 SVG 图纸；浏览器成功下载 v12 设计包。候选由协作者基于已有样例编制。

**验证证据**：[走查记录](walkthrough-2026-11-17.md)。记录说明实际操作、文件内容和未验证范围；本地项目数据和导出文件不作为源码发布。

**结论**：辅助流程可运行。在线模型调用、任意图片/链接自动重建、无辅助用户完成率和实物制作仍未验证。

## R1 · 页面与流程

**状态：待验收（页面实现完成，已做针对性浏览器走查）。**

**要解决的问题**：现有原型让用户理解保存参考、会话请求和候选导入等内部步骤；重复导航和分散产出使下一步不清楚。

**本轮范围**：开始制作 / 设计工作台 / 制作包；参考 / 适己 / 做法的单一导航；案例与项目继续；当前设计和候选区分；按采购、加工、装配呈现资料；明确版本和检查范围。

**复用基础**：现有项目、候选、检查、图纸和导出能力。本轮不因整理页面而宣称在线模型质量或工程能力提升。

**验收路径**：

1. 新用户从案例建立自己的项目，看到模型候选并采用。
2. 用户退出再继续同一项目，能找到当前阶段和下一步。
3. 在工作台调整尺寸，区分预览与已采用结果，能返回前一任务。
4. 查看制作包，找到采购、加工和装配内容及所对应的版本。
5. 返回设计继续修改，能识别资料是否需要重新生成。
6. 在小屏查看候选时，模型与主要动作同时可达。

**2026-11-17 验证记录**：

- 浏览器实际执行：从案例创建独立项目、采用候选、将座宽从 400 改为 420 mm、接受修改、查看制作包、返回首页并继续项目；尺寸和资料显示为当前版本。
- 首页输入置物架需求后创建项目并保存会话请求，明确显示等待当前聊天处理；无模型时点击适己阶段会提示先采用模型。
- 检查草稿制作包：下载被阻塞，图纸逐张标为草稿；受尺寸修改影响的连接显示待重新核对，并折叠旧方案说明。
- 查看桌面 1440×900 首页与工作台、小屏 390×844 制作包，长表格可横向滚动。
- JavaScript 语法检查通过；HTML ID 无重复，静态 DOM 引用完整；文档相对链接检查通过。
- 按项目约定未运行构建、单元测试或完整回归。既有测试断言仍需后续定向执行；本轮不声称测试套件通过。

**待验证项**：陌生用户独立完成率、不同浏览器与键盘无障碍、真实网络故障恢复、在线模型质量和实物交付。尚未完成全部验收，因此保持待验收。

**进入下一轮前**：记录完成项、未完成项、实际检查范围和可复现问题。未实现的子项仍保持待办，不能只因三页入口存在就视为整轮完成。

**Module 方向确认**：Module 作为人体工学与功能意图层纳入下一轮设计基线。它不新增顶层入口，先嵌入“尺寸”阶段；首个验证对象为 CAFE CHAIR 的“坐姿支撑”，覆盖座宽、座深、座高、靠背支撑和承载条件。第一阶段只验证模块目标、部件映射、修改预览和资料影响，不宣称已经具备通用人体工学求解器。

**Module MVP 已实现**：`Project.modules` 已进入设计数据和候选协议；样例会生成坐姿支撑模块，模块约束进入确定性检查；自然语言修改座板宽度时，候选同时更新部件和模块目标；尺寸任务与制作包显示同一版本的适配目标。尚未实现通用模块求解、人体轮廓叠加、置物/工作模块和模块级直接数值编辑。

**入口修正**：参考保存后不再要求用户重新输入产品链接或制作想法；主画布直接显示设计构思状态和下一步动作，补充参考作为次级操作。案例入口在已有参考后隐藏，避免流程分流。

## R1.1 · 参考到模型的闭环（2026-11-17）

**触发问题**：参考保存后曾停在“等待当前聊天处理”，页面没有可观察的模型结果；同时主画面和任务侧栏都放置生成入口，按钮状态不同步，用户看到入口却无法继续。

**本轮定义**：

```text
保存参考 → 展开设计构思 → 生成模型候选 → 中央预览 → 采用/放弃 → 尺寸与 Module
```

- 参考保存只做输入确认，不再要求重复填写链接或想法。
- 主画面保留唯一的“生成可编辑模型”入口；任务侧栏只说明当前阶段，不复制生成按钮。
- 默认 `prototype` 通道返回确定性的木质餐椅候选，并明确标注“本地原型候选”，不把它描述成真实识别或人体工学结论。
- 候选直接进入中央模型预览；采用后进入尺寸阶段，显示 CAFE CHAIR 的“坐姿支撑” Module、目标尺寸和受影响部件。
- 生成失败保留参考和当前设计，页面显示错误并允许重试；在线模型仍通过同一候选协议接入。

**验证结果**：浏览器实际走通文字参考、生成候选、中央预览、采用候选和进入尺寸阶段；采用后项目版本从 v2 到 v3，Module 显示座宽 400、座深 215、座高 450、靠背角 10°。已做 JavaScript 语法和 `git diff --check`，未运行构建、单测或完整回归。

**仍未完成**：本地原型只覆盖一把示例木椅；尚未实现任意图片的真实识别、曲面/隐藏结构推断、通用家具参数求解和在线模型质量验证。

## R1.2 · 人体模数与参考证据（2026-11-18）

**触发问题**：尺寸阶段只有只读目标值，用户无法输入和保存自己的身体数据；目标尺寸没有透明换算依据，也没有逐项确认。参考侧栏把候选操作、网页链接和文字参考混在一起，重复入口让流程看起来像弹窗任务。

**本轮实现**：

- 新增人体模数卡，支持身高、臀宽、臀膝长、腘窝高和鞋底厚度；输入支持 cm/mm，项目统一保存 mm。
- 新增“人体模数 → 家具尺寸”计算卡，显示公式、余量和建议值；建议不会静默覆盖模型。
- 新增逐项确认队列，按座高、座深、座宽、靠背角顺序一次确认一项，写入 `Module.confirmations`；全部完成后才显示 Module 已确认。
- 左侧参考改为参考证据卡片，显示类型、标题、摘要和链接；候选采用/放弃集中在中央候选栏，侧栏只解释当前状态。

**验证结果**：浏览器输入身高 170 cm、臀宽 40 cm、臀膝长 48 cm、腘窝高 42 cm、鞋底厚 2 cm，保存后计算出座高 395 mm、座深 440 mm、座宽 480 mm；连续确认四项后显示“已完成逐项确认”。参考侧栏显示单张文字参考证据卡。已运行 JavaScript 语法、Python 编译检查和 `git diff --check`；未运行完整构建、单测或回归测试。

**生成等待修正**：复现链接参考项目后确认 `/ai/status` 为 `prototype / ready`，生成请求约 1 秒返回候选；此前页面没有即时重绘，且残留的参考读取状态会误禁用按钮。现在点击后立即显示处理状态并锁定重复点击，候选返回后显示中央预览和采用操作。

## R3 · 交付与实物反馈

状态：计划中，依赖稳定设计数据和明确的加工范围。

重点验证可打印/可采购/可加工的资料和可理解的装配过程。加工者先独立读包，再在受控条件下验证样件；把退回原因和装配问题回写到设计规则及产品提示。

状态只使用“计划中、进行中、待验收、已验收”；只有完成所列验收后才能标记已验收。实现完成但未经用户/加工者试验的目标继续保留待验证说明。
