# Flatma 对齐矩阵

参考：[Flatma 帮助中心](https://flatma.com/zh/help/)（2026-11-17 查阅）。以下比较来自官方功能说明与 Junior 的本地走查，不等于已亲测 Flatma 的全部功能。

## 能力矩阵

| 能力 | Flatma 体验基线 | Create Junior 当前 | 对齐动作 |
|---|---|---|---|
| 参考进入 | AI 图片、草图、家具库、材料库 | 图片、链接、PDF、文字；AI 候选接口 | 保持证据链，补充草图/尺寸标注输入 |
| 可编辑模型 | 2D/3D 参数化编辑 | 直板/木条家具参数化部件和三维预览 | 做统一参数面板、拖拽与尺寸约束 |
| 材料与构件 | 板材、厚度、纹理方向、库存/供应商 | 材料与纹理方向、库存可选但不扣减 | 补充材料规格、余量和替代规则 |
| 连接与加工 | 连接件、孔槽、加工操作、干涉检查 | 孔槽、五金、连接和确定性检查；复杂榫头缺项 | 先做常见板式连接，再扩展加工特征 |
| 产出 | 下料/切割清单、钻孔图、技术图纸、下载 | 下料、A3 SVG、装配资料、ZIP 下载 | 对齐导出字段、图纸索引和打印体验 |
| 版本与协作 | 版本、分享、社区、制造商 | 不可变版本、恢复、候选接受；无社区 | 核心制造闭环完成后再做分享/社区 |
| 空间规划 | 房间布置、尺寸适配 | 非目标 | 暂缓，避免分散制造闭环 |

## 目标用户流程

`上传成品参考 → AI/手工标注 → 编辑部件与尺寸 → 选择材料和连接 → 检查干涉/覆盖 → 查看下料与钻孔图 → 下载并制作`。

对齐 Flatma 的“完整度”首先意味着这个核心制造闭环完整、状态清楚、结果可打印；社区、房间规划和制造商网络属于后续产品线。

## 分期

- **P0**：稳定项目模型、参数编辑、候选确认、检查、清单、图纸和 ZIP。
- **P1**：草图/尺寸标注、常用连接库、材料规格和余量、图纸标注拾取。
- **P2**：库存/供应商、分享、版本协作、社区和房间规划。

## 2026-11-17 实际走查与当前差距

已用 CAFE CHAIR 链接起步项目走通：保存参考 → 会话提交带版本的请求 → 导入真实部件候选 → 采用 → 座板宽度调整为 400 mm → 确认尺寸和加工条件 → 导入加工候选 → 采用连接 → 查看装配和图纸 → 确认 v12 → 从网页下载 ZIP。产物含 6 个部件、5 处连接、34 件五金、11 张 SVG 图纸、design.json 和 package.json。

本次由当前聊天承担设计协作，复用了仓库中已有的 CAFE CHAIR 几何/加工基线，并在证据与设定中标明。没有验证任意链接一键生成；没有调用外部在线模型。80 kg、室内和加工店制件是演示设定，不是用户真实需求，也不是承载认证。

入口现在区分三种通道：

- 会话协作：提交请求，当前聊天处理，再返回候选；不会自动唤起聊天。
- 样例体验：新建独立项目加载现成模型，不声称分析了用户参考。
- 在线 AI：服务端配置模型接口；字段齐全只代表已配置，仍需实测提供方调用和输出质量。

相对 Flatma，Junior 目前的优势是将成品参考、适己改制、来源依据与可制作资料放在同一项目中。核心弱项仍是自动化与通用性：参考识别、尺寸恢复和结构推断尚未完成可靠验证；编辑器缺少成熟的参数关联与尺寸约束；模板、材料和连接库覆盖有限；未实现成熟的板材排版优化与直接 DXF/PDF 导出；项目首页、恢复、生成失败重试与长任务反馈仍需统一。

下一阶段优先级：先实测一个在线视觉模型从参考到候选的成功率和失败恢复，再完善一类家具的约束编辑及材料/连接选型，最后打磨图纸、下料和交付。完整度应按陌生用户能独立完成的流程衡量，不能以按钮数量衡量。
