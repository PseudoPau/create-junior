# 开放体验评估 · 2026-11-24

对象：本仓库当前工作区（`main` + 未提交改动），服务 `http://127.0.0.1:8000`。
目的：判断能否开放给别人体验，并实际走一遍主流程，记录断点。

## 结论

- **可做 1:1 演示**：用 CAFE CHAIR 样例，从复原到下载加工包可以走通，产物是真的（模型、PDF、SVG、CSV、ZIP）。
- **不能公开自助**：用户带自己的参考进来会在第一步失败（本机未配在线 AI 密钥）；服务没有鉴权/多用户隔离，不能直接放到公网。
- **流程没达到 brief 的“最短路径”**：什么都不改走完仍要 18 次点击，其中 12 次是在确认没改过的尺寸、板件组和节点组。

## 已走通的样例路径

首页“打开椅子样例” → “就用这版，继续” → “保持原尺寸，直接核对” → 五项尺寸逐项“下一个” → “查看尺寸总览” → “确定尺寸，继续做法” → “从板件开始” → 板件/节点逐组“下一个” → “生成加工包” → 采购清单 / 加工资料 / 图纸预览 / 装配步骤 / ZIP。

亮点：模型始终是画面主体；尺寸标注可在三维视口里直接输入；“就用这版，继续”和“候选预览·尚未采用”区分清楚；图纸与 PDF 版面可读。

## 断点

| 级别 | 现象 | 证据 | 影响 |
|---|---|---|---|
| P0 | 自己的参考无法复原 | `.env` 中 `CREATE_JUNIOR_AI_API_KEY` 为空；提交链接/文字后任务失败 | 产品核心承诺（带参考进来）第一步就断，只能玩样例 |
| P0 | 不能公网开放 | 无登录；`GET /api/workbench/projects` 返回本机全部项目；导出按项目 id 直接下载 | 任何人都能读写本机 `.data`，不能作为公开链接发出 |
| P1 | “不改任何东西”仍要 18 次点击 | 样例入口 1 + 继续 1 + 跳过身体数据 1 + 五项尺寸 5 + 尺寸总览 1 + 做法 1 + 板件 4 + 节点 3 + 出包 1 | 与交接稿 v2 的 A02/A11“提交参考→继续→出包”冲突；其中 12 次是确认未改内容 |
| P1 | 刷新后加工包页丢失 | P1 生成后按 F5，URL 被改写为 `#step=M9`，回到“做法汇总”，只能重新生成 | 与产品设计“返回设计时项目和工作状态都保留”不一致；旧包在界面里没有入口（`GET /exports` 存在但前端未接） |
| P1 | 改座宽/座深被当作改款 | 样例保型档案 `adjustable_keys=["seat_height_mm"]`，`limits=[]`；改 400→420 mm 返回 `preservation_decision` | 五项适己尺寸里只有座高有校核范围，座宽/座深/两个角度实际都是“改款”分支，适己体验不完整 |
| P1 | 输入尺寸时页面跳走 | 在座宽标注输入 420，停顿约 600 ms 后自动预览并切到“这会改变原来的设计”，输入框消失，Enter 按不到 | 违反“输入→预览→Enter 采用”的单一动作；用户想改数字会先被带到另一个决定页 |
| P2 | 失败页曾出现字面 `null` | `web/studio.js` 把 `failed?null:...` 直接 append 到 DOM；已在本次修掉（`if(!failed)`） | 失败态观感；修复已用同一路径复验 |
| P2 | 角度页的输入提示仍是毫米示例 | 座面倾角/座背夹角页写“支持 430、43cm、450-20；角度使用 °” | 文案误导，非阻塞 |
| P2 | “座深”名称未定 | 产品文档 §8 第 6 项尚未决定；界面仍叫“座深” | 与“座板前后长度”的术语约定不一致 |
| P2 | 提前点“加工包”落点混乱 | 刚进适己就点 04 加工包，落到做法汇总，同时出现“尺寸需要重新核对”和“出包前还有 1 项：请确认原物尺度” | 用户会以为还有多个未知阻塞，实际只是没走核对 |

## Brief 梳理

**写清楚了**：定位（成品家具复原 + 适己 + DIY）、核心规则（默认保留原椅）、四步流程、三方分工（AI / 产品规则 / 用户 / 加工店）、首版范围（只做餐椅、平直板件）和“不做什么”。

**作为开放体验规格，还缺四块**：

1. **交付形态**：本地单机、私有链接还是公开站点？谁部署、谁付模型费用、数据存哪、怎么删除。现在产品设计把“在线模型提供方/费用/数据处理”列为待决，这会直接决定能不能开放。
2. **准入与隔离**：公开体验至少需要访问控制、项目隔离、限流和密钥管理；当前一个本机进程 + `.data/` 目录 + 无鉴权 API，只适合自己用。
3. **开放门槛**：现有验收是“加工者能读包”和“5 位用户 4 位完成”，没有定义首响时间、失败恢复、参考成功率、刷新恢复、并发这些开放体验指标。
4. **适己的可用范围**：brief 说“只改与使用者不合的几项”，但没有承诺样例椅上有几项真的可调。现在只有座高，其余进入改款，brief 和体验之间的落差需要写明或补齐。

**三句与实现不符、建议改 brief 或改代码**：

- “第 2、3 步是推荐顺序，不是门槛” → 现在五项尺寸和 7 个做法组都必须逐组确认才能出包。
- “没有单独的确认步骤，核对是出包的条件” → 从用户动作看，就是 12 次确认。
- README“旧版本仍可下载” → 新工作台没有旧包入口，刷新后当前包也不恢复。

## 达到可开放体验的最小条件

**路线 A：只做样例演示（1–2 天）**
1. 明确标注“样例体验，不支持上传自己的参考”，隐藏或置灰会失败的入口；首页主按钮引导到样例。
2. 修掉刷新丢包、旧包入口、提前点加工包的落点。
3. 修尺寸输入被自动跳转打断的问题（Enter 才提交预览，或冲突提示留在原页）。
4. 用 3–5 位目标用户按脚本走一遍，记录卡点。

**路线 B：真开放（先解决 P0）**
1. 配一个可用的视觉模型密钥，拿 3 把不同参考做真实复原，记录成功率与失败原因；没有这一步，不能对外说“AI 能复原”。
2. 加访问控制与项目隔离（至少私有 token / 单用户部署说明），再考虑公网。
3. 补齐座宽/座深的保型范围，或明确“这几项只能改款”。
4. 完成路线 A 的 2–4。
5. 由未参与设计的加工者独立读一次包。

## 给演示者的建议

演示时只走样例，不要现场提交自己的链接；先说明“这是改制样例，不是 AI 识别结果”。如果要发链接给别人，先别发公网地址，录屏 + 本机演示更稳。
