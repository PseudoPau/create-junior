# 路线图与交接项

产品方向已认可，按 R1 → R2 → R3 推进。每轮以可验证的用户结果收尾；实现和验证记录分开，具体见 [迭代说明](iterations.md)。

## 已有原型基线

- 独立本地 Web 工作台和项目存储。
- 参考、结构化候选、部件、连接、图纸和清单共用项目版本。
- 明确区分会话协作、在线适配器和固定案例。
- CAFE CHAIR 会话辅助走查完成设计采用、适己调整、加工方案、图纸预览和 ZIP 下载。

这份基线未证明任意参考自动重建、在线模型端到端质量或普通用户独立完成。

## R1：页面与流程（待验收）

**用户结果**：知道从哪里开始、目前做到哪一步、可以怎样继续和取得资料。

- 整理开始制作 / 设计工作台 / 制作包三个主要页面。
- 工作台统一为参考 / 适己 / 做法，合并重复导航。
- 保留案例和我的项目入口，提供明确的继续操作。
- 区分当前设计与待采用候选；生成/交接/失败状态各有对应提示。
- 制作包围绕采购、加工和装配组织，显示版本与检查范围。

**完成条件**：在现有案例上走通新入口、继续项目、修改与采用、制作包和返回设计；小屏候选预览不被侧栏遮挡。记录实际浏览器走查和相关检查结果。未完成的状态恢复或交付能力明确留在待办中。

## R2：一类家具自主完成（计划中）

**用户结果**：无需开发者导入 JSON，就能从有效参考得到方案，并按目标调整。

- 确定首发类型和支持边界；建议评估低矮、固定层板、已知连接模板的置物架。
- 接入并实测一个在线视觉模型，记录有效输入成功率与失败原因。
- 建立家具级参数关联，修改尺寸时维护板厚、孔位、连接及用户空间约束。
- 材料和连接变化触发受影响约束的重新检查。
- 覆盖链接不可读、缺尺度、服务失败、过期候选和重新打开项目的恢复路径。

**完成条件**：陌生用户能独立完成参考、适己和做法；固定案例与自动生成分别统计。建议以 5 位无 CAD 经验用户试验、至少 4 位独立完成为首轮目标，尚无当前达成数据。

## R3：制作资料可交付（计划中）

**用户结果**：清楚该采购什么、交给加工者什么、怎样装配。

- 可打印资料、可读清单与编号一致的零件/连接图。
- 按步骤展示部件、五金、工具、方向和装配顺序。
- 区分草稿、送审/询价与满足相应条件的制作资料。
- 由未参与设计的加工者只看包、不读聊天和 JSON，判断加工准备是否完整。
- 受控样件验证装配，记录实际问题，再调整品类支持边界。

**完成条件**：加工者能明确识别所需信息和剩余核对项；模型、清单、图纸同版；样件问题可追溯到设计并修正。下载成功不能替代实物验证。

## 需要负责人决定的事项

- 首发家具类型和尺寸、材料、连接的支持范围。
- 默认加工路径，以及允许用户切换的方式。
- 在线模型提供方、部署方式、费用和数据处理规则。
- 首发交付是否止于送审资料，或提供明确的专业复核流程。

不为未确认的能力承诺发布日期。社区、空间规划、供应商网络和丰富专业建模工具在核心路径验证后再排期。
