# Create Junior

把喜欢的成品家具，做成适合自己的版本。

Create Junior 帮普通用户把一把喜欢的成品椅子原样复原成可编辑模型，只改不适合自己的地方，再生成能交给加工店的加工包。首发只做餐椅。项目独立运行，数据保存在本机。

> 当前分步接入新版交互：已准备五项尺寸核对、板件／节点分组及在线 AI 自动任务的后端；新版视觉稿确认后再接入页面布局。在线通道尚未完成真实密钥调用验收；固定案例独立提供，不作为参考识别结果。

## 为什么做这个产品

“我喜欢这件家具，但它放不下”“我想换材料”“我愿意自己装，却不知道该买什么、如何加工”——这些需求通常要跨过 CAD、木工和图纸阅读的门槛。

Junior 把这条路径组织成四个问题。用户决定目标和取舍，AI 把参考和意图转成可编辑方案，产品规则维护模型与图纸、清单的一致。

## 产品流程

核心规则：默认保持原椅子，只改它与你不合、而且这把椅子允许改的地方。

| 步骤 | 你在回答 | 你得到 |
|---|---|---|
| 1 复原 | 这是我要的那把椅子吗 | 第一版可编辑模型，带尺寸、默认做法和这把椅子的特征 |
| 2 适己 | 它哪里不适合我 | 填一次身高、坐高、臀宽和主要坐姿，只处理不合适的几项 |
| 3 做法 | 我打算怎么做 | 沿用默认做法，只处理必须选择的项，也可以主动修改 |
| 4 出包 | — | 加工包：我买什么、交给加工店什么、我怎么装 |

页面有三个：开始制作、设计工作台、加工包。第 1–3 步都在设计工作台里围绕同一个模型完成，第 2、3 步可以跳过。

目标流程见 [交接稿 v2](docs/design-handoff-v2.md)，本轮修正与实际边界见 [会话 Agent 实施记录](docs/session-agent-iteration.md)。适己不再使用前端身体比例公式；已有有效做法沿用，只有未解决项进入核对。

产品细节参考 [Flatma 的连续工作流程](https://flatma.com/zh/help/)，重点学习项目恢复、模型编辑、材料连接、图纸与交付之间的衔接。

## 当前能体验什么

- 保存图片、链接、文字与 PDF 参考；会话工具按选页读取 PDF 文本和原图，并标明尚未读取的页。
- 提交参考即进入工作台并建立任务；在线模式自动读取参考、调用模型、检查并返回结果，会话模式保留手动领取。区分处理中、待补充、失败、过期和结果就绪。
- 显式加载 CAFE CHAIR 案例，在独立项目预览并采用可编辑部件。
- 通过会话协作导入设计候选，或使用已实现的本地指令进行部分尺寸调整。
- CAFE CHAIR 样例包含“坐姿支撑”Module；Module 面板把模度人参考值和用户输入放在同一处，加工包保留同一版本的适配目标。
- 适己只要求身高、坐高、臀宽和主要坐姿，保存个人档案及项目快照。AI 建议需要对应当前身体数据；缺少依据时保持未知，不强行改变原椅子。
- 模型尺寸标注支持直接输入与加减换算，预览后 Enter 保存、Esc 取消；越过已知保型规则时明确作为改款处理。尺寸联动目前覆盖六板样例构造，其他结构由 Agent 返回关联修改。
- 查看和编辑部件、加工特征、连接和五金，预览模型与装配。
- 查看确定性检查、版本历史、A3 SVG 图纸及下料/五金信息。
- 生成版本加工包：可编辑 JSON 模型、SVG/PDF 图纸、采购/下料/五金 CSV 和装配说明。旧版本仍可下载，不与新设计混用。

2026-11-17 的 [样例走查](docs/walkthrough-2026-11-17.md) 获得 6 个部件、5 处连接、34 件五金、11 张图纸。候选复用了已有样例基线，由当前聊天协作编制；这次走查不是任意图片自动建模的验证。

当前支持平直板/木条、简单平面斜切、孔和槽。通用人体工学求解、通用材料/连接库、整板排版和 DXF 仍未实现。模型检查未覆盖整椅承载、稳定性、疲劳、真实加工公差和所有装配可达性。

## 本地启动

需要 Python 3.12 或更高版本、[uv](https://docs.astral.sh/uv/) 和支持 WebGL 的现代浏览器。在项目根目录执行：

```powershell
uv sync
uv run python -m playwright install chromium
Copy-Item .env.example .env
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --env-file .env
```

已有 `.env` 时保留原配置，跳过复制。macOS/Linux 可用 `cp .env.example .env` 创建初始配置。

打开 [本地工作台](http://127.0.0.1:8000/)。首次体验可选择 CAFE CHAIR 案例；不需要在线模型密钥。项目数据保存在 `.data/`，不会随源码提交。

## AI 如何参与

AI 是贯穿项目的家具设计协作者：理解参考、识别使用 Module、追问必要信息、提出部件和做法、将修改要求转成候选，并解释影响。候选采用后才成为当前设计。Module 记录人体与功能意图，部件记录实际几何，规则负责两者的约束和版本一致性。

产品规则负责字段、几何与连接检查、版本一致性和资料派生；用户负责用途、空间、偏好和方案取舍；实际工艺与产品未覆盖的工程问题需要加工店或专业人员核对。

当前有以下通道：

- **本地原型生成（旧接口）**：`CREATE_JUNIOR_AI_PROVIDER=prototype`。固定样例用于开发，当前工作台不以它替代参考识别。
- **会话协作**：`CREATE_JUNIOR_AI_PROVIDER=session`。页面保存设计任务，当前聊天使用 [会话工具](docs/session-agent.md) 领取、读取上下文、预览检查、修正并返回；用户无需编辑 JSON。
- **案例体验**：加载已准备好的模型，供编辑和出包体验。它不会分析你的参考，也不会被当作 AI 识别结果。
- **在线 AI（新配置默认）**：`CREATE_JUNIOR_AI_PROVIDER=openai`。网页创建任务后自动领取，读取网页正文与图片／PDF 页图像，调用视觉模型，最多三轮检查修正；只返回建议或待采用模型。补充回答后继续处理，取消及版本变化会阻止晚到结果覆盖设计。单进程任务总时限六分钟，重启后需重新提交中断任务。

使用 OpenAI 时，在服务端 `.env` 设置 `CREATE_JUNIOR_AI_PROVIDER=openai`、`CREATE_JUNIOR_AI_BASE_URL=https://api.openai.com/v1`、`CREATE_JUNIOR_AI_MODEL=gpt-6.2-astra`，并仅在本机填写 `CREATE_JUNIOR_AI_API_KEY`。模型可替换；示例采用支持图片输入与结构化输出的 [GPT-6.2 Astra](https://developers.openai.com/api/docs/models/gpt-6.2-astra)。兼容服务使用 `openai_compatible` 及其提供的根地址和模型。配置格式见 [.env.example](.env.example)，保存后重启服务；更新代码不会覆盖已有 `.env`。

页面设置只展示通道和字段填写状态。字段齐全不等于模型连接或输出质量已经验证。

## 新版流程后端接入

- `GET /api/workbench/projects/{id}/review` 读取五项实测尺寸、板件组、节点组和确认状态；读取不改变项目。
- `POST .../review/start` 显式启用新版核对；`POST .../review/confirm` 每次确认一项，提交 `expected_revision`、`category`、`id` 和 `fingerprint`。当前模型改变后，仅保留仍匹配的确认。旧项目不会自动获得确认，也不会自动开启新门槛。
- `GET .../modules/{module_id}/comparison?canonical=true` 提供座高、座宽、座深、座面倾角、座背夹角的新语义；旧比较接口保持兼容。`edit-preview` 接受座背夹角，复用原有保型与候选提交；座面倾斜等未覆盖构造返回 `agent_required`，需要完整关联方案。
- `POST .../design-runs` 可指定 `requested_result_kind=advice`，仅允许建议与说明变化。普通设计任务默认 `design`，仍需用户采用才写入模型。
- 新核对启用后，加工包要求五项尺寸、板件组、节点组全部确认；出包仍绑定单一项目版本。前端接入留待视觉稿确认。

当前分组只合并可证明完全等价的重复件和节点，尚未覆盖任意镜像加工的等价识别。在线参考预算为每份 PDF 至多六页、最多十二张图片、单张四 MB、合计十二 MB；超限或缺失明确失败。网页读取只包含正文摘录，不自动抓取网页中的产品照片，需要用户提供图片证据。新增测试已编写，本轮未完成运行验收。

## 迭代状态

- **原型基线**：本地项目、结构化候选、模型/检查/图纸、版本和样例出包。
- **R1 · 待验收**：已实现开始制作、设计工作台和加工包三个页面，完成案例改尺寸、项目继续与资料查看的针对性浏览器走查。
- **R1.3 · 待验收**：会话任务、原版基线、统一预览提交、模型标注编辑及版本加工包已实现，验证范围见迭代记录。
- **R2 · 计划中**：在餐椅上验证在线生成、关联尺寸和做法调整，让用户独立完成。
- **R3 · 计划中**：可打印交付、装配步骤、加工者审阅及受控实物验证。

## 代码结构

- `app/main.py`：Web 服务入口。
- `app/workbench/`：项目、参考、候选、版本、AI 适配、检查与资料生成。
- `web/`：三维工作台与图纸界面。
- `examples/`：可重复体验的设计候选样例。
- `tests/`：领域和接口测试。
- `docs/`：产品设计、实现边界与迭代记录。
