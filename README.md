# Create Junior

把喜欢的成品家具，做成适合自己的版本。

Create Junior 是面向普通用户的家具复刻与 DIY 适己化工作台。你可以从照片、产品链接或一个想法开始，逐步确定外观、尺寸、材料和连接，再把同一份设计变成采购、加工与装配资料。项目独立运行，采用本地优先的数据存储。

> 当前是开发中的原型。默认通道是本地原型生成：可以完整走一遍“参考 → 构思 → 模型候选 → 采用 → 尺寸/Module”。候选用于验证交互，不代表真实图片识别或人体工学核验；任意参考自动重建、在线模型端到端质量和实物制作结果尚未验证。

## 为什么做这个产品

“我喜欢这件家具，但它放不下”“我想换材料”“我愿意自己装，却不知道该买什么、如何加工”——这些需求通常要跨过 CAD、木工和图纸阅读的门槛。

Junior 希望把这条路径组织成可理解的设计过程。用户决定目标和取舍，AI 把意图转为可编辑方案，产品规则维护模型与图纸、清单的一致性。第一次价值是看到能改的家具，最终价值是按自己的条件把它做出来。

## 产品流程

产品设计采用三个主要页面，正在按 [迭代计划](docs/roadmap.md) 落地：

1. **开始制作**：提供图片、链接与文字；从案例起步，或继续自己的项目。
2. **设计工作台**：围绕 **参考 → 尺寸 → 材料 → 资料** 调整同一模型。尺寸阶段先确认当前“使用模块/适配目标”，再把人体、动作和空间约束传递到部件、连接和资料。
3. **制作包**：回答 **我买什么、交给加工店什么、我怎么装**。采购、图纸和装配资料绑定同一版本。

“适己”会贯穿整个项目：换板厚或连接方式影响内部空间时，应重新核对原先的使用目标，给出具体取舍。

产品细节参考 [Flatma 的连续工作流程](https://flatma.com/zh/help/)，重点学习项目恢复、模型编辑、材料连接、图纸与交付之间的衔接。Junior 的重点是成品参考理解、适己目标和新手制作引导。

## 当前能体验什么

- 保存图片、链接和文字参考；PDF 目前作为附件保存，不承诺自动解析。
- 在本地原型通道下，参考保存后主画面只保留一个生成入口；点击后中央直接出现一版“本地原型候选 · 木质餐椅”，可以采用或放弃。
- 显式加载 CAFE CHAIR 案例，在独立项目预览并采用可编辑部件。
- 通过会话协作导入设计候选，或使用已实现的本地指令进行部分尺寸调整。
- CAFE CHAIR 样例包含“坐姿支撑”Module；尺寸候选会同步显示模块目标、受影响部件，制作包保留同一版本的适配目标。
- 尺寸阶段支持保存身高、臀宽、臀膝长、腘窝高和鞋底厚度，cm/mm 输入统一换算为 mm；系统显示透明的座高、座深、座宽建议，并一次确认一个尺寸。
- 查看和编辑部件、加工特征、连接和五金，预览模型与装配。
- 查看确定性检查、版本历史、A3 SVG 图纸及下料/五金信息。
- 确认当前设计版本后下载包含设计数据与 SVG 图纸的 ZIP。

2026-11-17 的 [样例走查](docs/walkthrough-2026-11-17.md) 获得 6 个部件、5 处连接、34 件五金、11 张图纸。候选复用了已有样例基线，由当前聊天协作编制；这次走查不是任意图片自动建模的验证。

当前支持范围以平直板/木条、简单平面斜切、孔和槽为主。Module 目前先验证坐姿支撑目标和部件映射；通用人体工学求解、置物/工作 Module、完整家具级参数约束、通用材料/连接库、板材排版优化和直接 PDF/DXF 导出仍在计划中。模型检查未覆盖整件家具的承载、稳定性、疲劳、真实加工公差及所有装配可达性；设计确认和下载成功不代表这些项目已通过。

## 本地启动

需要 Python 3.12 或更高版本、[uv](https://docs.astral.sh/uv/) 和支持 WebGL 的现代浏览器。在项目根目录执行：

```powershell
uv sync
Copy-Item .env.example .env
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --env-file .env
```

已有 `.env` 时保留原配置，跳过复制。macOS/Linux 可用 `cp .env.example .env` 创建初始配置。

打开 [本地工作台](http://127.0.0.1:8000/)。首次体验可选择 CAFE CHAIR 案例；不需要在线模型密钥。项目数据保存在 `.data/`，不会随源码提交。

## AI 如何参与

AI 是贯穿项目的家具设计协作者：理解参考、识别使用 Module、追问必要信息、提出部件和做法、将修改要求转成候选，并解释影响。候选采用后才成为当前设计。Module 记录人体与功能意图，部件记录实际几何，规则负责两者的约束和版本一致性。

产品规则负责字段、几何与连接检查、版本一致性和资料派生；用户负责用途、空间、偏好和方案取舍；实际工艺与产品未覆盖的工程问题需要加工店或专业人员核对。

当前有三个明确分开的通道：

- **本地原型生成（默认）**：`CREATE_JUNIOR_AI_PROVIDER=prototype`。根据已保存参考生成一版确定性的木质餐椅候选，用来验证完整页面流程；它不是图片识别结果。
- **会话协作**：`CREATE_JUNIOR_AI_PROVIDER=session`。页面保存设计请求，由当前聊天中的协作者处理并通过候选接口返回；网页不会自动调用聊天。适合接入人工/当前聊天协作。
- **案例体验**：加载已准备好的模型，供编辑和出包体验。它不会分析你的参考，也不会被当作 AI 识别结果。
- **在线 AI**：内置 OpenAI-compatible 适配器。配置视觉模型后可以发起生成；实际提供方和模型的端到端质量仍需验证。

在线模式需要在服务端 `.env` 设置 `CREATE_JUNIOR_AI_PROVIDER=openai_compatible`，并填写 `CREATE_JUNIOR_AI_BASE_URL`、`CREATE_JUNIOR_AI_API_KEY`、`CREATE_JUNIOR_AI_MODEL`。接口地址使用服务商提供的兼容根地址，模型需支持图片输入和所需 JSON 输出。配置格式见 [.env.example](.env.example)，保存后重启上面的服务命令。

页面设置只展示通道和字段填写状态。字段齐全不等于模型连接或输出质量已经验证。

## 迭代状态

- **原型基线**：本地项目、结构化候选、模型/检查/图纸、版本和样例出包。
- **R1 · 待验收**：已实现开始制作、设计工作台和制作包，完成案例改尺寸、项目继续与资料查看的针对性浏览器走查。
- **R2 · 计划中**：在一种家具上验证在线生成、关联尺寸和做法调整，让用户独立完成。
- **R3 · 计划中**：可打印交付、装配步骤、加工者审阅及受控实物验证。

具体范围、完成条件和验证记录见 [路线图](docs/roadmap.md) 与 [迭代说明](docs/iterations.md)。实际变更记录在 [CHANGELOG](CHANGELOG.md)。

## 代码结构

- `app/main.py`：Web 服务入口。
- `app/workbench/`：项目、参考、候选、版本、AI 适配、检查与资料生成。
- `web/`：三维工作台与图纸界面。
- `examples/`：可重复体验的设计候选样例。
- `tests/`：领域和接口测试。
- `docs/`：产品设计、实现边界与迭代记录。
